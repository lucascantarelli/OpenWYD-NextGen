# QA-06 — Recusas genéricas abrem caixa vazia no cliente

**Aberto em:** 05/11/2026 (terceira rodada de QA in-game)
**Tipo:** mensagem fora do padrão do cliente
**Prioridade:** média (não quebra jogo; esconde o motivo de qualquer recusa)

## Sintoma

Várias ações não fazem nada visível: a recusa chega como `MSG_MessageBoxOk` com um
corpo de 4 bytes (o código interno `Notice`). O cliente 7662 lê esse pacote como
`{int Useless1; int Useless2; char String[96]}` (`Basedef.h:1534-1541`), então abre
um diálogo **sem texto**. O jogador só vê "não aconteceu nada".

A rodada de 05/11 já corrigiu o caso irmão: `MSG_MessagePanel` com `HEADER.ID`
diferente de 0 é descartado (`TMScene.cpp:1371`), e era isso que escondia as
mensagens de refino (`refine_feedback.go`) e as de party/trade (`party.go`,
`trade.go` passaram a responder com o texto legado).

## Causa

`handler/notice.go` → `notify()` envia `MSGBoxOk` com o código numérico e deixa a
string vazia. O mapeamento `Notice` → linha do `Language.txt` nunca foi feito para
a maioria dos códigos.

## Correção

1. Carregar/embutir as linhas do `Release/TMsrv/run/Language.txt` (cp1252, uma
   linha por id) e mandar `SendClientMessage` (MessagePanel, ID 0) com o texto,
   caindo no `MessageBoxOk` só quando não houver id confirmado.
2. Ids já levantados nesta rodada (Language.h → texto):

| id | símbolo | quando |
|----|---------|--------|
| 74 | `_NN_Only_To_Equips` | poeira/gema em alvo que não é equipamento |
| 75 | `_NN_Cant_Refine_More` | refino no teto / `EF_NOSANC` |
| 76 | `_NN_Fail_To_Refine` | falha no refino |
| 79 | `_NN_No_Key` | portão trancado sem chave |
| 80 | `_NN_Wrong_Trade_Packet1` | pacote de troca inválido |
| 82 | `_NN_Already_Trading` | já negociando |
| 85/86/87 | `_NN_Each_Of_You_Havent_Space` / `_NN_You_Have_No_Space_To_Trade` / `_NN_Opponent_Have_No_Space_To` | troca sem espaço |
| 91 | `_NN_Not_Connected` | alvo offline |
| 113/83 | `_NN_Not_Enough_Money` / `_NN_Havent_Money_So_Much` | gold insuficiente |
| 119/120/121/122 | party: membro, líder, já em grupo, cheio | convite/grupo |
| 176 | `_NN_Refine_Success` | refino com sucesso |
| 215 | `_NN_Party_Level_Limit` | diferença de nível no grupo |
| 452 | `_NN_FUll_CARRY` | inventário cheio |

3. Teste: cada `Notice` mapeado deve sair como `MsgMessagePanel` com `ID == 0` e o
   texto exato — hoje os testes de troca checam `MsgMessageBoxOk` +
   `noticeCode` (`trade_test.go`, `TestTradeNoRoomRollsBack`).

## Evidência

`tmserver/internal/handler/notice.go` (comentário do `notify`), `Basedef.h:1534`,
e a terceira rodada de QA: "as mensagens de level up / exp / recusas não aparecem".
