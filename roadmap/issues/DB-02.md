# DB-02 — Teste de `down` e revisão dos índices de auditoria

**Fase:** revisão · **Depende de:** DB-01 (concluída) · **Esforço:** S · **Estado:** ✅ concluída (06/11/2026)

## Objetivo

Fechar os dois itens da REVIEW-05 que não são roles/restore: provar que o `down` do baseline deixa o
schema limpo num banco efêmero e decidir, com `idx_scan`, quais dos índices de auditoria valem manter.

## Resultado

### `down` do baseline

O pacote de migrations **não tinha** `0001_schema.down.sql` — o `db-baseline.sh` só o gerava em
`_baseline/` no modo dry-run. O arquivo foi criado (`DROP SCHEMA public CASCADE; CREATE SCHEMA public`)
e `scripts/db-down-check.sh` o prova num banco descartável, com verificação por catálogo:

```
   up: tables=50 indexes=… sequences=… composite_types=…
   down: tables=0 indexes=0 sequences=0 composite_types=0 characters=NULL
ok: up+down do baseline verificado (schema vazio, sem objeto órfão)
```

A consulta final é `to_regclass('public.characters')` = `NULL` mais contagem em `pg_class`,
`pg_indexes` e `pg_type` (`typtype='c'`) — não leitura de arquivo. O banco descartável é derrubado.

### Índices de auditoria (19)

Medição em `pg_stat_user_indexes` + `pg_stat_user_tables` na base viva, sem reset de estatística:

| Índice | idx_scan | Tabela | Decisão |
|---|---:|---:|---|
| `account_admin_audit_target_idx` | 0 | 0 kB | **fica** — serve `WHERE target_id = $1` e `ORDER BY id DESC` (account_admin.go) |
| `donate_shop_audit_action_created_idx` | 14 | 0 kB | **fica** — filtro `action` + `created_at` (donate_revenue.go) |
| `account_admin_audit_actor_idx` | 0 | 0 kB | cai — nenhuma query filtra por `actor_id` |
| `character_admin_audit_character_idx` / `_moderator_idx` | 0 | 0 kB | caem — auditoria só é escrita, não consultada no código |
| `content_rate_audit_key_idx` / `_moderator_idx` | 0 | 0 kB | caem — idem |
| `daily_reward_audit_reward_item_id_idx` | 0 | 8 kB / 4 linhas | cai — idem |
| `donate_shop_audit_shop_item_id_idx` / `_subject_idx` | 0 | 0 kB | caem — o filtro real usa `action`/`created_at` |
| `drop_rate_audit_slot_idx` / `_moderator_idx` | 0 | 0 kB | caem — idem |
| `guild_admin_audit_guild_idx` / `_moderator_idx` | 0 | 0 kB | caem — idem |
| `item_effect_audit_item_idx` / `_moderator_idx` | 0 | 0 kB | caem — idem |
| `mob_carry_audit_template_idx` / `_moderator_idx` | 0 | 0 kB | caem — idem |
| `npc_audit_npc_id_idx` | 0 | 8 kB / 7 linhas | cai — nenhuma SELECT filtra por `npc_id` em produção |

`0005_drop_unused_audit_indexes.up.sql` aplica as 17 remoções (`DROP INDEX IF EXISTS`, idempotente).
As PKs continuam: são identidade/unicidade, não índice de consulta.

Prova num banco vazio (0001→0005 + seeds, com `W2PP_DB_NAME=freshcheck ./scripts/db-roles.sh`
antes — grants de schema são por banco): `npc catalogue ready content_definitions=6099`,
`to_regclass('public.characters')` resolve e a contagem de índices de auditoria não-PK é **2**.

## Testes/verificação

```bash
./scripts/db-down-check.sh                       # up+down em base descartável
docker exec openwyd-db-1 psql -U postgres -d postgres \
  -c "select relname, indexrelname, idx_scan from pg_stat_user_indexes where relname like '%audit%'"
```
