# DB-02 — Teste de `down` e revisão dos índices de auditoria

**Fase:** revisão · **Depende de:** DB-01 (concluída) · **Esforço:** S · **Estado:** ⏳ proposta

## Objetivo

Fechar os dois itens da REVIEW-05 que não são roles/restore: provar que o `down` do baseline deixa o
schema limpo num banco efêmero e decidir, com `idx_scan`, quais dos índices de auditoria valem manter.

## Contexto/evidência (06/11/2026)

- `0001_schema.down.sql` é `DROP SCHEMA public CASCADE; CREATE SCHEMA public;` — destrutivo por
  definição, então o teste é de fumaça (o schema some sem erro), nunca de reversibilidade de dado.
- A review pedia "revisar os 19 índices de auditoria"; o número precisa sair de
  `pg_indexes`/`pg_stat_user_indexes` no banco atual, não do texto de 05/11.

## Passos

1. Teste em base efêmera: aplicar `0001_schema.up.sql`, depois `.down.sql`, e validar que
   `to_regclass('public.characters')` é NULL e que o `up` roda de novo do zero.
2. Rodar o teste no CI (junto do job de banco da CI-02, se ele já existir).
3. Para cada índice de auditoria, medir `pg_stat_user_indexes.idx_scan` após uso real; remover os que
   nunca são lidos **e** cujo dado não justifique (a decisão fica registrada aqui com a medição).
4. Views de relatório: só criar quando houver consumo real, com `security_invoker`.

## Arquivos

- `internal/store/migrate_test.go` (teste de `down`)
- `.github/workflows/` (job de banco)
- `internal/migrations/` (migration de remoção de índice, se aprovada)
