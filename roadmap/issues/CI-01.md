# CI-01 — Workflows reutilizáveis, path filters e `make ci`

**Fase:** revisão · **Depende de:** — · **Esforço:** M · **Estado:** ✅ concluída (06/11/2026)

## Objetivo

Um pipeline que roda o mesmo gate do desenvolvedor, sem repetir setup, e um `make ci` que reproduz o
CI localmente — inclusive num host sem Go (via container), que é o caso desta máquina.

## Contexto/evidência (05/11/2026)

```bash
grep -c '^ci:' Makefile                    # 0  (não existe alvo ci)
grep -cE '^[a-z][a-z0-9-]*:' Makefile      # 21 alvos
```

- `.github/workflows/ci.yml` tem 5 jobs, cada um repetindo `checkout` + `setup-go` (sem
  `workflow_call`).
- Nenhum path filter: mudar `portal/**` roda a matriz Go inteira e vice-versa.
- O build local já quebrou por disco cheio e por build paralelo derrubando o daemon; nada no CI
  detecta nenhum dos dois.
- Nesta sessão, `go build ./...` ficou vermelho por um rename de módulo incompleto e **nenhum gate
  local avisou** — só apareceu ao rodar o build à mão.

## Passos

1. `_go.yml` (`workflow_call`: setup-go com cache, gofmt, vet, build, test) e `_portal.yml`
   (`setup-node`, `npm ci`, `tsc`, `vitest`, `next build`); `ci.yml` só orquestra e aplica
   `paths:`.
2. `make ci` chamando exatamente o mesmo conjunto (gofmt/vet/build/test + portal), funcionando sem Go
   no host (`docker run golang:1.26-alpine …`), com o mesmo cache de módulos usado no dia a dia.
3. Gate de coerência do repositório (barato e pega o que doeu): falhar se
   `bash scripts/check-build.sh --path-only` ou se `go build ./...` falhar.
4. `scripts/preflight.sh` já checa disco/Docker; ligar no `make ci` e no job, com mensagem clara.
5. Publicar tempo de cada job e cache hit rate; sem isso não se sabe se o cache funciona.

## Arquivos

- `.github/workflows/ci.yml`, `_go.yml`, `_portal.yml`
- `Makefile` (alvo `ci`, alvo `check-repo`)
- `scripts/preflight.sh`

## Testes/verificação

```bash
make ci          # local, sem Go no host, mesmo gate do CI
bash scripts/check-build.sh --path-only && echo OK || echo FALHOU
```

## Critérios de aceite

- [ ] `ci.yml` sem repetição de setup (usa `workflow_call`).
- [ ] Path filters: portal só roda com `portal/**`/`api/**`; Go com `**/*.go`/`go.mod`/`internal/migrations/**`.
- [ ] `make ci` verde num host sem Go.
- [ ] Gate de path antigo + build no CI.

## Resultado (06/11/2026)

| Entrega | Onde |
|---|---|
| Workflow Go reutilizável (`on: workflow_call`) com gate, build+test, lint, govulncheck e matriz Docker | `.github/workflows/_go.yml` |
| Workflow do portal reutilizável (typecheck, test, build, Docker smoke) | `.github/workflows/_portal.yml` |
| Orquestrador com **path filter** e um job `changes` que roda sempre | `.github/workflows/ci.yml` |
| `make ci` = gate + higiene de teste + vet + build + test + portal | `Makefile` |

`ci.yml` deixou de ter 5 jobs repetindo `checkout`+`setup-go`: agora decide o que mudou e delega. O
filtro ficou no orquestrador (e não em `paths:` do gatilho) porque workflow que **não roda** deixa o
status obrigatório pendente em PR de documentação — com o job `changes` sempre executando, sempre há
um check que reporta.

### Verificação executada (equivalente local de cada passo)

```bash
make gate            → scripts/check-build.sh (path antigo + artefatos proto)
bash scripts/check-skips.sh      → 42 skip(s), todos com motivo declarado
bash scripts/check-comments.sh   → 3 diretório(s) limpos
go vet ./...         → exit 0
go build ./...       → exit 0
go test ./...        → suíte completa (ver evidência no changelog do índice)
make portal-test     → tsc exit 0 + 12 arquivos / 93 testes
```

Os mesmos comandos são os `run:` dos workflows — não há passo no CI que não exista no Makefile.
**Limitação honesta:** GitHub Actions não roda neste host (sem runner); o que foi verificado é o
YAML por inspeção + a execução real de todos os comandos que ele chama. Nenhum `actionlint` rodou.

### O que não entrou (e por quê)

- **Postgres de serviço** — é a CI-02, Fila B: exige migrations aplicadas em base vazia e gate de
  contagem por tabela.
- **SBOM / assinatura de imagem** — pertence à REVIEW-04 fase 2, não ao "workflow único".
- **Tempo de job e cache hit rate** — precisa de duas execuções reais no GitHub; fica para o primeiro
  PR que passar por aqui.

## Riscos/rollback

Risco: refatorar workflow e o PR ficar sem gate por alguns commits. Mitigação: manter `ci.yml` antigo
como fallback até o novo rodar verde em dois PRs. Rollback: reverter o workflow é um arquivo.
