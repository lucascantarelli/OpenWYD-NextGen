# CI-02 — Job de banco: migrações em base vazia a cada PR

**Fase:** revisão · **Depende de:** CI-01 · **Esforço:** M · **Estado:** ⏳ proposta

## Objetivo

Toda migração ser aplicada do zero no CI, com contagem por tabela comparada ao baseline — o gate que
hoje só existe como script manual (`scripts/db-baseline.sh`) e que já evitou regressão silenciosa.

## Contexto/evidência (05/11/2026)

- `internal/migrations/` tem o baseline squasheado (`0001_schema.up.sql` + seeds) e o boot aplica em
  ordem; `store.Migrate` roda no `dbserver` e no `webserver`.
- `scripts/db-baseline.sh` valida em base vazia (18k+ linhas de referência) mas **não roda no CI**.
- Consequência real desta sessão: com a stack fora do ar, o `dbserver` falhou por DNS do `db`
  (`lookup db ... no such host`) e seguiu; nenhum job reproduz o boot contra Postgres limpo.
- O CI atual não tem `services: postgres`, então uma migração quebrada só aparece no deploy.

## Passos

1. Job `db` com `services: postgres:17-alpine`, healthcheck e `POSTGRES_PASSWORD` descartável.
2. Rodar as migrações com o próprio runner Go (mesmo `store.Migrate`), não com `psql` à parte — o
   caminho testado tem de ser o caminho de produção.
3. Comparar contagem por tabela com o baseline versionado (`scripts/db-baseline.sh --check`) e falhar
   em divergência, listando tabela e delta.
4. Job gêmeo para o boot completo: subir `dbserver` + `tmserver` apontando para o Postgres do job e
   exigir os logs de catálogo (`npc catalogue ready`, `NPCs`/geradores registrados).
5. Rodar `TestE2ESmokeLogin` contra esse stack efêmero (tags `e2e`, versão 12000).

## Arquivos

- `.github/workflows/db.yml` (novo) ou job no `ci.yml`
- `scripts/db-baseline.sh` (modo `--check` para CI)
- `internal/migrations/**` (sem edição; só verificação)

## Testes/verificação

```bash
bash scripts/db-baseline.sh --check
go test -tags=e2e -run TestE2ESmokeLogin ./tmserver/internal/world/ -v
```

## Critérios de aceite

- [ ] Job aplica todas as migrações em base vazia e falha se contagem divergir.
- [ ] Boot completo (db + dbserver + tmserver) validado no job.
- [ ] `TestE2ESmokeLogin` verde no stack efêmero.
- [ ] Tempo do job < 10 min (cache de módulos do CI-01).

## Riscos/rollback

Risco: job de banco virar gargalo de fila. Mitigação: rodar só quando `internal/migrations/**`,
`store/**` ou `dbserver/**` mudarem. Rollback: `continue-on-error` na primeira semana.
