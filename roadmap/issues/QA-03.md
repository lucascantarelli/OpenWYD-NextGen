# QA-03 — `/gm item <id> <qtd>` derruba o cliente

**Fase:** QA in-game · **Depende de:** issue-122 · **Esforço:** S · **Estado:** ⏳ confirmado na sessão de 05/11

## Objetivo

Entregar um item empilhado por comando de GM sem fechar o cliente — ou recusar o comando com
mensagem, quando o item não empilha.

## Contexto / evidência

Sessão de 05/11/2026, personagem `TestHT` (conta `test`, admin):

```
msg="gm command" cmd=item args="412 20"
msg="gm item" account=test item=412 amount=20 slot=7
```

O servidor aceitou e respondeu; **o cliente crashou imediatamente**. O item 412 é
`Poeira_de_Oriharucon`, cujo catálogo traz `EF_VOLATILE 4` e **nenhum `EF_AMOUNT`**:

```
item_index | name                 | volatile | effects
        412 | Poeira_de_Oriharucon |        4 | []
```

`handler/gm.go:gmItem` clampa a quantidade num limite **global** (`maxStackAmount = 120`) e escreve
`EF_AMOUNT` sem perguntar se aquele item aceita contagem:

```go
if qty > maxStackAmount { qty = maxStackAmount }
it := world.Item{Index: int16(id)}
if qty > 1 { setItemAmount(&it, qty) }
```

O caminho já tem o predicado correto em `handler/item.go` (`canWriteItemAmount`/`isSplittable`), usado
no split/merge — o comando de GM simplesmente não o consulta. **Hipótese** (falta captura de pacote):
o cliente recebe `CNFGetItem` com um efeito que não espera para esse índice e derruba.

## Passos

1. Capturar o tráfego do crash (`0x0275`/`CNFGetItem`) para confirmar o campo que estoura.
2. Em `gmItem`, só escrever `EF_AMOUNT` quando `canWriteItemAmount(it)`; caso contrário, entregar
   `qty` unidades em slots distintos (uma por slot) ou recusar com aviso.
3. Teste de unidade: `gmItem` de item não empilhável com `qty>1` não produz item com `EF_AMOUNT`.
4. Retestar no cliente: `/gm item 412 20` e `/gm item 400 20` (empilhável) — nenhum crash.

## Arquivos

- Alterados: `tmserver/internal/handler/gm.go`, `tmserver/internal/handler/gm_test.go`
- Referência: `tmserver/internal/handler/item.go` (`canWriteItemAmount`, `maxStackAmount`)

## Testes / verificação

```bash
go test ./tmserver/internal/handler/ -run TestGMItem -v
```

Saída esperada: caso novo para item não empilhável verde; `amount` só aparece em item que aceita.

## Critérios de aceite

- [ ] `/gm item 412 20` não derruba o cliente (entrega distribuída ou recusa explícita).
- [ ] `/gm item 400 20` continua entregando 20 unidades num slot.
- [ ] Teste cobrindo o item não empilhável.
- [ ] Evidência anexada (log do `gm item` + cliente vivo).

## Riscos / rollback

- Risco: mudar a distribuição quebrar teste que espera um único slot. Mitigação: só muda para item
  que não aceita `EF_AMOUNT`.
- Rollback: comando é de teste; reverter o commit restaura o comportamento anterior.
