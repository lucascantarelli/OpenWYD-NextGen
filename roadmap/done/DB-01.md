# DB-01 — Papéis no Postgres, DSN por serviço e restore testado

**Fase:** revisão · **Depende de:** — · **Esforço:** M · **Estado:** ⏳ proposta

## Objetivo

Nenhum serviço conectar como superusuário; o portal poder ler só o que precisa; e um restore do
backup realmente validado (não só um `pg_dump` que roda sem erro).

## Contexto/evidência (05/11/2026)

O compose conecta **todos** os serviços como `postgres`:

```bash
grep -n "W2PP_DB_DSN\|POSTGRES_USER" docker-compose.yaml
# 34: W2PP_DB_DSN: postgres://postgres:${POSTGRES_PASSWORD:-dev}@db:5432/postgres
# 58: W2PP_DB_DSN: postgres://postgres:${POSTGRES_PASSWORD:-dev}@db:5432/postgres
```

- `docs/analysis/banco-de-dados.md` §10 já registra como P1 as roles `openwyd_app`/`openwyd_ro` e o DSN
  sem superusuário — continua aberto.
- O invariante 7 do `AGENTS.md` (“a web nunca escreve estado de personagem vivo”) hoje depende só do
  código: o DSN não impede nada.
- `scripts/db-backup.sh` existe; não há `db-restore.sh` nem registro de restore validado.

## Passos

1. Migration nova (nunca reutilizando número) criando `openwyd_app` (DML no que o boot usa),
   `openwyd_ro` (SELECT no que o portal lê) e `openwyd_migrator` (DDL), com
   `ALTER DEFAULT PRIVILEGES IN SCHEMA public`.
2. DSN por serviço no compose: `tmserver`/`dbserver`/`webserver` → `openwyd_app` (o `dbserver` aplica
   migração como `openwyd_migrator`, ou com `search_path`/role `SET ROLE`), portal → `openwyd_ro`.
3. `scripts/db-restore.sh`: restaurar o último dump em banco descartável, comparar contagem por tabela
   e falhar em divergência; registrar a data do último restore validado em `docs/analysis/banco-de-dados.md`.
4. Teste de `down` do baseline em base efêmera (fumaça: `DROP SCHEMA … CASCADE` sem erro).
5. Revisar os 19 índices de auditoria com `pg_stat_user_indexes.idx_scan` após uma semana de uso.

## Testes/verificação

```bash
docker compose up -d db && docker compose exec db psql -U postgres -c "\du"
bash scripts/db-restore.sh --check
bash scripts/db-baseline.sh
```

## Critérios de aceite

- [ ] Nenhum serviço com DSN de superusuário no compose.
- [ ] Boot completo funcionando com as roles (tmserver registra geradores, dbserver responde).
- [ ] Portal autenticando com `openwyd_ro` e nenhuma escrita fora de `delivery_queue`.
- [ ] Restore validado com data e contagem registradas.
- [ ] `idx_scan` medido para os 19 índices, com remoção dos não usados.

## Riscos/rollback

Risco: GRANT incompleto quebrar o boot (padrão já visto). Mitigação: aplicar em base efêmera com
`store.Migrate` + boot completo antes do dev; rollback é voltar o DSN por variável de ambiente.
