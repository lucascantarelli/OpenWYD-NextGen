# DB-03 — `sapphire_balance` sem linha única em banco novo (quote do manto falha)

**Fase:** revisão · **Depende de:** DB-01/DB-02 · **Esforço:** S · **Estado:** ✅ concluída em 06/11/2026

## Objetivo

Garantir a linha singleton de `sapphire_balance` em qualquer banco — novo ou restaurado — para que
`QuoteKingdomCape` não devolva `no rows in result set`.

## Resultado

- `internal/migrations/0007_sapphire_balance_singleton.up.sql` insere a linha com os defaults da
  tabela (`version=1`, custos `8/8`) usando `ON CONFLICT (singleton) DO NOTHING`, preservando preço
  já ajustado num banco existente. O `down` remove a linha **somente** se ela ainda estiver nos
  defaults; preço alterado por compra é dado de jogo e não é apagado.
- `store.QuoteKingdomCape` devolve os defaults quando a linha não existe (defesa para banco
  restaurado sem a migration) e `PurchaseKingdomCape` faz `INSERT … ON CONFLICT DO NOTHING` dentro
  da transação antes do `SELECT … FOR UPDATE`, materializando a singleton e serializando a compra.
- O `INSERT` de conveniência do teste de integração foi removido; o teste agora prova o estado
  migrado do zero. Um segundo teste apaga a linha e prova a reparação no quote/compra.

## Evidência

Banco descartável `citest` (o helper derruba o schema `public`, por isso nunca o banco de dev):

```bash
W2PP_TEST_DSN='postgres://postgres:dev@127.0.0.1:5432/citest' \
  go test -tags=integration ./internal/store/ -run 'KingdomCape' -count=1 -v
```

Saída: `TestPurchaseKingdomCapeRevisionIsSingleWinner` **PASS** (26,55 s),
`TestQuoteKingdomCapeRepairsMissingSingleton` **PASS** (25,50 s), pacote `ok` em 56,54 s.

Banco vivo, após reconstruir e subir o `dbserver` (a migration roda no boot):

```text
schema_migrations: 0007_sapphire_balance_singleton
sapphire_balance:   1|8|8
count:              1
```

## Critérios de aceite

- [x] Banco recém-migrado responde ao quote sem intervenção manual.
- [x] Compra concorrente continua com um único vencedor e revisão avançando.
- [x] Job `database` da CI-02 verde sem o `INSERT` de conveniência no teste.

## Riscos/rollback

`ON CONFLICT DO NOTHING` impede sobrescrever preço ajustado. O rollback da migration remove apenas a
linha intacta nos defaults; se a linha já foi comprada, ela permanece. Remover a migration sem rodar
o `down` também é seguro: o store passou a criar a singleton na primeira compra.

## Fora do escopo

Não altera a interface do portal nem o fluxo de compra; a prova é de persistência e concorrência.
