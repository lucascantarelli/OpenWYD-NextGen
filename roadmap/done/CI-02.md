# CI-02 — Job de banco: migrações em base vazia a cada PR

**Fase:** revisão · **Depende de:** CI-01 · **Esforço:** M · **Estado:** ✅ concluída (06/11/2026) — boot/e2e em [CI-03](../issues/CI-03.md)

## Objetivo

Toda migração ser aplicada do zero no CI, com o `down` do baseline verificado por catálogo — o gate
que antes só existia como script manual (`scripts/db-down-check.sh`) e que já evitou regressão
silenciosa.

## Entrega

- `.github/workflows/db.yml` (novo): job `database` com `services: postgres:17-alpine`
  (`pg_isready`), `actions/checkout@v5`, `actions/setup-go@v5` (`go-version-file: go.mod`) e três
  passos obrigatórios, sem `|| true` e sem passo opcional:
  1. `go build ./...`
  2. `go test -tags=integration ./internal/store/ -run TestBaselineDown -count=1 -v`
  3. `go test -tags=integration ./internal/store/ -count=1`
- `internal/store/baseline_down_integration_test.go` (novo, tag `integration`): cria um banco
  descartável, aplica `0001_schema.up.sql`, conta os objetos, aplica `0001_schema.down.sql`, confere
  o catálogo e derruba o banco. É o mesmo caminho dos arquivos embedded do runner — não usa
  `docker exec` nem psql externo.
- O passo 3 inclui `TestMigrateAndSaveAccount`, que roda `store.Migrate` (0001..0005 + seeds) num
  schema vazio e depois prova a idempotência: é o `up` completo que a issue pedia.
- `internal/store/store_integration_test.go`: `resetTestSchema` passou a derrubar/recriar o schema
  `public` inteiro. A lista manual de tabelas tinha envelhecido (`account_admin_audit` de fora) e o
  `Migrate` seguinte morria com `42P07 relation already exists`; o schema inteiro não tem como
  envelhecer.
- `Makefile`: `make test-db` (mesmo comando do job, exige `W2PP_TEST_DSN` de banco descartável) e
  `make db-down-check` (verificador manual, com o aviso de que apaga o schema).

## Falhas encontradas e corrigidas no caminho

1. **Reset incompleto** — a lista de `DROP TABLE` não tinha `account_admin_audit`; corrigido com
   `DROP SCHEMA public CASCADE; CREATE SCHEMA public` (o teste passa a medir o schema real).
2. **Dois testes liam migrations arquivadas** — `TestKefraMigrationExistingCharacters` e
   `TestNightmareMigrationExistingCharacters` liam `0022`/`0024.down.sql`, que o squash moveu para
   `_archived/`. Foram reescritos como contrato do baseline (`kefra_ticket`,
   `nightmare_entries`, `last_nightmare_use`: NOT NULL DEFAULT 0, estado existente intacto).
3. **Estado de runtime semeado** — `kefra_state` e `world_event_*` vêm dos seeds; os testes de
   concorrência agora zeram o estado de propósito.
4. **`sapphire_balance` sem linha única** — o quote do manto falha em banco novo e também no banco
   vivo (`SELECT *` → 0 rows). Registrado em [DB-03](../issues/DB-03.md); o teste de corrida garante a
   singleton só para medir a revisão.

## O que ficou fora (e por quê)

O boot completo (`dbserver` + `tmserver`) e o `TestE2ESmokeLogin` dependem de conteúdo que **não
está no git** (os 17 MiB de `HeightMap.dat`/`AttributeMap.dat`, LEGACY-02). Publicar esse binário no
CI é uma decisão de infra própria: [CI-03](../issues/CI-03.md). Nada disso foi escondido atrás de
`continue-on-error`; simplesmente não é um passo do job de banco.

## Critérios de aceite

- [x] Job aplica todas as migrações em base vazia (`TestMigrateAndSaveAccount`) e roda os testes de
      integração de banco.
- [x] `down` do baseline roda e é verificado por catálogo (0/0/0/0 e `public.characters` NULL).
- [x] Falha se o `down` deixar objeto órfão (assert no teste, não só log).
- [x] Tempo do job compatível: build + down + suíte em ~5,5 min localmente; o CI tem cache do
      `setup-go` (CI-01).
- [ ] Boot completo + `TestE2ESmokeLogin` no CI — movido para CI-03 com justificativa de conteúdo.
- [x] `actionlint` verde e nenhum passo silenciado.

## Riscos/rollback

Risco: job sempre ligado em todo PR custar ~6 min de runner. Mitigação: cache do `setup-go`; se
virar gargalo, adicionar `paths` no gatilho **sem** transformar o check em opcional (um job que não
roda deixa o required check pendente). Rollback: remover o workflow — o gate local continua em
`make test-db`.
