# DB-05 — Auditoria do rename `character` → `characters`

Fase 6 · Depende de DB-04 · Esforço S

## Objetivo

Garantir que store, migrations e o processo em execução concordam com o nome real da tabela, para
o login nunca voltar a falhar com `relation "character" does not exist` (42P01).

## Contexto/evidência

O erro de 11:46/12:08 vinha de um dbserver cujo binário era anterior à migration 0003 e consultava
`FROM character`. A migration já estava aplicada (11:32), mas o processo antigo continuava rodando
com o SQL velho — rename correto no banco, runtime desatualizado.

## Verificação

- `schema_migrations`: `0003_rename_character_to_characters` aplicada em 06/11 11:32.
- Catálogo vivo: `pg_tables` tem `characters`, `character_admin_audit`, `character_pvp_stats`;
  **não existe** `character`.
- Código Go não tem `FROM character`/`JOIN character` (só mensagens de erro e docs); o store usa
  `characters` (`ListCharacters`, `LoadCharacter`, `SaveCharacter`).
- Stack reconstruída às 13:23 (dbserver/tmserver/tmserver2) e login e2e nos dois canais sem 42P01.

```bash
docker exec openwyd-db-1 psql -U postgres -d postgres -tAc \
  "SELECT tablename FROM pg_tables WHERE schemaname='public' AND tablename LIKE 'character%';"
# characters
# character_admin_audit
# character_pvp_stats

docker exec openwyd-db-1 psql -U postgres -d postgres -tAc \
  "SELECT version FROM schema_migrations WHERE version LIKE '0003%';"
# 0003_rename_character_to_characters

docker compose logs --since=5m db | grep -c 42P01
# 0
```

## Critérios de aceite

- [x] Banco vivo só com `characters` (nenhuma tabela `character`).
- [x] Nenhuma query Go usa o nome antigo.
- [x] Login e seleção e2e nos canais 1 e 2 sem 42P01.
- [x] Processos em execução reconstruídos a partir do código atual.

## Riscos/rollback

O rename é irreversível na prática (dados). O rollback seria uma migration que renomeia de volta,
o que reintroduz a palavra reservada — não recomendado.
