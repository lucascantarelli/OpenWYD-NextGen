# Evidência — auditoria das instruções de IA (2026-11-12)

> **Escopo:** `.agents/skills/`, `AGENTS.md`, roteador e referências em `roadmap-rust/` e `docs/`.
> **Registro canônico:** [`roadmap-rust/changelog.md`](../../../roadmap-rust/changelog.md).
> **Data da coleta:** 2026-11-12.
> **Objetivo:** manter apenas instruções que o agente usa, remover duplicação/obsolescência e
> provar que as referências e os gates continuam íntegros.

## Referência usada

Li efetivamente, em 2026-11-12, a documentação oficial do Codebuff/Freebuff:

- **Codebuff Docs — “Project Instructions”** (`https://www.codebuff.com/docs/tips/knowledge-files`):
  `AGENTS.md` é lido primeiro no início do chat e seguido pela sessão inteira; o texto recomenda
  manter o arquivo curto e linkar os docs profundos que o agente abre quando precisa; no Freebuff
  Cloud a leitura vai até ~64 KB.
- **Codebuff Docs — “Skills”** (`https://www.codebuff.com/docs/tips/skills`): skills ficam em
  `.agents/skills/<nome>/SKILL.md`; a `description` é o que o agente vê para decidir carregar; o
  conteúdo completo do `SKILL.md` só é carregado quando a skill é invocada; cada skill deve ter um
  propósito único e descrição específica.

Nenhuma regra foi inventada a partir de documentação inacessível. Se qualquer uma dessas páginas
não estivesse disponível, a base seria declarada explicitamente; não foi o caso.

## Conta de contexto: sempre ativo vs sob demanda

Método: `linhas = conteúdo.split('\n').length` (conta a última linha mesmo sem newline), `bytes =
Buffer.byteLength` e `tokens ≈ bytes / 4`; arquivos contados com `find .agents/skills -type f`.

Escopo da conta: o conteúdo que pode entrar no contexto do agente — `AGENTS.md` (sempre ativo) e
os corpos dos `SKILL.md` (carregados um a um quando o gatilho dispara). Nenhum outro arquivo é
lido em todo turno: `.agents/skills/README.md` é o roteador sob demanda. Recursos anexos de skill
(`references/`, `scripts/`, `LICENSE`, `README.md` do roteador) **não** são carregados
automaticamente e ficam fora desta soma; o total de bytes de `.agents/skills/` é reportado à parte.

## Duplicação/contradição resolvida

1. `AGENTS.md` repetia catálogo de skills, tabela de pastas, comandos e fontes que já estavam no
   roteador e em `docs/`; agora aponta para eles.
2. `ui-ux-practices` descrevia outro produto e não tinha caminho válido no WYD; removida.
3. `finishing-a-development-branch` pressupunha commit/PR e `go test ./...`; removida.
4. `writing-plans` apontava para `docs/superpowers/` inexistente; reescrita para o fluxo real.
5. `wyd-database` e `wyd-rust-db` repetiam schema/migrations; fundidas.
6. `wyd-server-ops` ainda citava `tmserver`; atualizada para o compose atual.
7. Skills Rust citavam stubs Go já removidos como “sucessoras”; notas eliminadas.

### O que foi corrigido

- Skill genérica de manutenção: removidas as seções **Claude.ai-specific**, **Cowork-specific**, o empacotamento
  via `present_files`, os exemplos de relatório/commit e a comparação cega; o loop repetido no fim
  foi eliminado. Referências ao host foram generalizadas para “the agent”. Mantidos o fluxo de
  criação, progressive disclosure, o loop de eval, a otimização de descrição e os recursos
  `agents/`, `references/`, `scripts/` e `eval-viewer/`.
- `rust-test-quality`: reduzida de 91 para 45 linhas. A taxonomia, a matriz por crate e a higiene
  detalhada continuam em `docs/arquitetura/testes.md`; a skill mantém apenas as decisões de gate,
  os comandos e o checklist que o agente usa ao escrever/revisar teste.
- `docs/rust/00-visao-estrutura.md`: o snapshot de 15 pastas não lista mais skills Go como se
  fossem o estado vigente; aponta para as 23 atuais e para o roteador.
- `docs/rust/03-progresso.md`: a linha do PROC-18 não repete nomes antigos como estado atual;
  registra 23 skills ativas e as sucessoras removidas/fundidas.
- `docs/rust/07-ia-e-bots.md`: a referência de harness agora é `wyd-rust-testing` + PROC-18, sem o
  alias `wyd-testing-bots` como se fosse uma skill vigente.

Não houve remoção, fusão ou criação de skill nesta revisão; o inventário continua com **23**. As
menções a nomes removidos que restam estão limitadas a registros históricos: `roadmap-rust/changelog.md`,
`docs/manual-técnico/skills.md` (tabela de sucessão), esta evidência, `FASE-09`, o ADR 0010, a
pesquisa de 2026-11-10 e o log do `03-progresso`. Nenhuma delas é instrução ativa ou caminho de skill.

## Limitações

- Em uma execução intermediária do `make check`, o teste `sistema_telemetry` falhou com
  `ConnectionReset` no cliente HTTP local; três execuções isoladas e o `make check` final
  passaram. É uma falha intermitente de socket, não relacionada às remoções (o teste já havia
  passado nas execuções anteriores).
- `mkdocs` não está instalado neste host; o gate de links foi executado como varredura relativa
  própria (arquivos Markdown, links relativos, ignorando blocos de código). Não foi possível rodar
  `mkdocs build --strict`.
- `docs/rust/00-visao-estrutura.md`, `docs/rust/03-progresso.md` (histórico) e o changelog antigo
  preservam nomes de skills Go como **registro histórico**; não são instruções ativas nem caminhos
  de skill vigentes.
- Nada foi commitado ou enviado ao remoto.
